# RAG: поиск и генерация

## Что такое RAG в нашем проекте

RAG = Retrieval-Augmented Generation.
Сначала находим релевантные документы, потом передаём их в LLM,
чтобы модель отвечала на основе реальных данных, а не «из головы».

В нашем случае:

1. Корпус — описания клиентов из Credit Card Customers.
2. Поиск — BM25 по этим описаниям.
3. Генерация — LLM формирует ответ с рекомендацией.

## Корпус

### Источник

Credit Card Customers (Kaggle).
Файл `data/BankChurners.csv`.

### Преобразование в текст

Каждая строка CSV → одно описание клиента.

Поля, которые попадают в текст:

- `Customer_Age` — возраст;
- `Gender` — пол;
- `Income_Category` — доход;
- `Card_Category` — тип карты;
- `Months_on_book` — сколько месяцев клиент с банком;
- `Total_Trans_Amt` — сумма транзакций;
- `Total_Trans_Ct` — число транзакций;
- `Contacts_Count_12_mon` — обращения в поддержку;
- `Attrition_Flag` — ушёл / остался.

Пример описания:

```
Клиент 45 лет, жен. Доход $60K–$80K. Карта Platinum.
С банком 36 месяцев. Транзакций за год: 120.
Сумма транзакций: $4500. Обращений в поддержку: 3.
Статус: ушёл.
```

Описания генерируются на русском языке скриптом `corpus.js`.
Это позволяет использовать русские стоп-слова при поиске.

### Размер корпуса

Полный датасет — 10 127 документов (~9 МБ JSON).
Индекс строится в браузере за доли секунды, поиск — миллисекунды.
Если корпус вырастет существенно — IndexedDB или backend.

## Поиск: BM25

### Параметры

- `k1 = 1.5`
- `b = 0.75`

Это стандартные значения. Если benchmark покажет плохие
результаты, можно подобрать заново.

### Предобработка

1. Приведение к нижнему регистру.
2. Удаление знаков препинания.
3. Токенизация по пробелам (буквы и цифры, юникод).
4. Замена «ё» на «е» — чтобы «ушёл» совпадал с «ушел» в запросе.
5. Словарь форм слов статуса: «ушла», «ушли», «уходят» → «ушёл»;
   «осталась», «остаются» → «остался». Это самый частый признак
   в вопросах менеджера, а полноценный стеммер избыточен.
6. Стоп-слова — минимальный список (и, в, на, с, по) плюс слова,
   есть в каждом документе (клиент, лет). Список русский,
   потому что корпус описаний — на русском.

### Реализация

Используется собственная реализация (~120 строк, `app/bm25.js`):
постинг-листы по терминам, IDF по формуле Robertson,
скоринг за один проход по постингам запроса. Для 10 127 документов
полный поиск занимает единицы миллисекунд, внешние библиотеки
(bm25-turbo, fast-bm25) не понадобились.

Раньше рассматривались варианты: библиотека `bm25-turbo` (WASM,
работает в браузере) и `fast-bm25` (TypeScript) — запасные варианты.

Интерфейс `app/bm25.js`:

```js
export function buildIndex(docs) { ... }
export function search(query, k) { ... }
```

### Вход и выход

- Вход: строка запроса, число `k`.
- Выход: массив `{ doc, score }`, отсортированный по убыванию.

## Генерация: LLM

### Промпт

Шаблон промпта:

```
Ты — помощник менеджера по удержанию клиентов.
Ответь на вопрос пользователя, опираясь только на факты
из приведённых документов. Если данных недостаточно,
скажи об этом прямо.

Вопрос:
{query}

Документы:
{documents}

Ответ:
```

### Провайдеры

- WebLLM — основной провайдер: модель работает в браузере на WebGPU,
  ключ не нужен. Библиотека (`@mlc-ai/web-llm`) подключена локально —
  `app/vendor/web-llm.js`, CDN (esm.run, jsdelivr, unpkg) — запасные
  варианты на случай устаревания локальной копии.
- Модель: `Qwen2.5-3B-Instruct-q4f16_1-MLC` (~2 ГБ, хорошо понимает
  русский). Запасная — Qwen2.5-1.5B (~1 ГБ) для слабых устройств.
  Веса скачиваются с Hugging Face при первом запуске и кешируются
  в браузере. Внимание: в актуальных версиях web-llm ID моделей
  без префикса организации («Qwen2.5-3B-…», а не «Qwen/Qwen2.5-3B-…»).
- `mock` — локальная заглушка; включается автоматически, если WebLLM
  недоступна (нет WebGPU или нет доступа к Hugging Face), чтобы поиск
  и интерфейс оставались работоспособными. Ручное переключение —
  через `app/config.js` (`llmProvider: "webllm" | "mock"`).

### Ограничения

- Контекст модели ограничен — передаём не больше 5 документов.
- Если ответ не опирается на документы — помечаем как ненадёжный.
- Таймаут вызова — 60 секунд (первая генерация компилирует шейдеры WebGPU
  и может быть долгой; при обрыве по таймауту частичный ответ сохраняется).
- Ответ модели показывается потоково, по мере генерации.

## Benchmark

### Набор

Файл `benchmark/questions.json`:

```json
[
  {
    "query": "Клиент 45 лет, карта Platinum, транзакции упали",
    "relevant_ids": ["C12345", "C67890"]
  }
]
```

### Метрики

- **Recall@5** — доля релевантных клиентов в топ-5.
- **Precision@5** — доля релевантных среди топ-5.
- **MRR** — средний обратный ранг первого релевантного.

### Запуск

```
node benchmark/run.js
```

Результат сохраняется в `benchmark/results.json`.

## Что проверяется

- Корпус построен: `node corpus.js` → `data/corpus.json` (10 127 документов).
- BM25 работает: `npm test`, `npm run benchmark`.
- WebLLM отвечает потоково, источники показываются с оценкой BM25
  и оценкой оттока.

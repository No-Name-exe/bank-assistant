# Архитектура

## Обзор

Приложение — статическая веб-страница на HTML/CSS/JS.
Пользователь вводит вопрос, система ищет похожие описания клиентов
через BM25 и формирует ответ с помощью LLM.

На КТ1 работает только интерфейс и заглушки поиска и LLM.
Реальный поиск и вызов модели добавляются после КТ1.

## Компоненты

Интерфейс прототипа разделён на `index.html`, `style.css` и `app.js`; поиск и LLM пока остаются заглушками. Модули `bm25.js`, `llm.js` и `corpus.js` появятся после КТ1. Ниже — целевая архитектура.

1. **Интерфейс (index.html, style.css, app.js)**
   - прокручиваемый список чатов с удалением выбранного чата и кнопка «Новый запрос»;
   - закреплённый заголовок чата и необязательная сворачиваемая форма клиентских признаков; в свёрнутом виде форма показывает краткую сводку;
   - поля формы для признаков из `BankChurners.csv` (профиль, продукты и стаж, активность, транзакции, кредитный лимит), без ID клиента, целевого статуса и рассчитанных классификатором выходов;
   - переключение между основными и полными данными на широком экране; мобильная форма показывает только основные признаки;
   - переписка с растущим по мере ввода полем сообщения и кнопкой отправки справа;
   - список источников рядом с ответом;
   - индикатор загрузки;
   - сообщения об ошибках и пустом результате;
   - прокрутка страницы отключена; список чатов и переписка прокручиваются независимо без видимых полос, а раскрытые поля данных при необходимости — внутри своего блока с тонкой полосой и неподвижным заголовком;
   - на мобильном экране список чатов открывается выдвижной панелью из заголовка чата; рядом с заголовком находится кнопка «Новый запрос».

2. **Модуль поиска (bm25.js)**
   - строит индекс по корпусу описаний клиентов;
   - функция `search(query, k)` возвращает топ-k документов
     с оценками BM25.

3. **Модуль подготовки корпуса (corpus.js)**
   - читает CSV с признаками клиентов;
   - превращает каждую строку в текстовое описание;
   - отдаёт массив документов `{ id, text, meta }`.

4. **Модуль LLM (llm.js)**
   - принимает вопрос и найденные документы;
   - формирует промпт;
   - вызывает LLM через API или WebLLM;
   - возвращает текст ответа.

5. **Контроллер (app.js)**
   - связывает интерфейс, поиск и LLM;
   - обрабатывает состояния: загрузка, успех, ошибка.

## Поток данных
На КТ1 интерфейс и обработчики находятся в отдельных файлах `index.html`, `style.css` и `app.js`; поиск и генерация реализованы заглушками.

1. Пользователь вводит вопрос в index.html.
2. Интерфейс объединяет заполненные поля клиента и текст сообщения в запрос; поля можно не заполнять, если признаки указаны в сообщении.
3. app.js проверяет, что сообщение не пустое, и может ли определить в форме или сообщении признаки клиента.
4. Если признаки клиента не обнаружены, интерфейс сообщает, что нужно добавить описание клиента, и поиск не запускается.
5. Если признаки есть, app.js вызывает bm25.js → search(query, k).
6. bm25.js возвращает массив найденных документов { doc, score }.
7. app.js передаёт запрос и найденные документы в llm.js → ask(query, documents).
8. llm.js формирует промпт, вызывает LLM и возвращает текст ответа.
9. app.js отрисовывает сообщение пользователя, ответ и источники в index.html.

```
Пользователь → index.html → app.js
                              │
                              ├──▶ bm25.js ──▶ найденные документы
                              │
                              └──▶ llm.js  ──▶ текст ответа
                                              │
                                              ▼
                                       index.html
                                       (ответ + источники)
```


## Корпус документов

Источник: Credit Card Customers (Kaggle).

Каждая строка CSV превращается в текст:

> «Клиент 45 лет, доход $60K, карта Platinum,
> 3 обращения в поддержку за год,
> транзакции упали на 40% за квартал,
> статус: ушёл».

Документ = одно описание клиента.
Это даёт текстовый корпус для BM25 без ручной разметки.

## Хранение данных

corpus.js — одноразовый скрипт. Он читает BankChurners.csv и создаёт data/corpus.json. Приложение читает только готовый JSON и CSV не парсит.

Если данные меняются: обновить CSV → запустить node corpus.js → получить новый data/corpus.json → закоммитить.

На КТ1 — небольшой JSON-файл (`data/corpus.json`),
загружаемый вместе со страницей.

На КТ2, если корпус вырастет, — IndexedDB или backend.

## Конфигурация

Файл `config.js`:

```js
export const CONFIG = {
  topK: 5,
  llmProvider: "mock", // "mock" | "openai" | "webllm"
  apiKey: "",
  model: "",
};
```

Ключи API не коммитятся. Для локальной разработки — .env
или ввод в интерфейсе.

## Ошибки и состояния
| Состояние | Поведение |
|---|---|
| Запрос пустой | Кнопка неактивна |
| Идёт поиск | Индикатор загрузки |
| Ничего не найдено | Сообщение «Похожих клиентов не найдено» |
| LLM недоступна | Показать найденные источники без ответа |
| Ошибка сети | Сообщение с предложением повторить |

## Тестирование

- `tests/search.test.js` — проверка BM25 на фиксированном корпусе.
- `tests/scenario.test.js` — сквозной прогон основного сценария.
- `benchmark/run.js` — прогон benchmark-набора и сохранение результатов.

На КТ1 тесты не обязательны, но структура папок готова.
